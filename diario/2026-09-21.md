# 21/09/2026 — PWA no mobile: cache-bust dos ícones, nome completo legível e verificação automática de versão

## 1. Ícones do PWA com nomes versionados (fura cache teimoso do mobile)

O Chrome no Samsung A53 ignorava query string no manifest/ícones: mesmo com `?v=` novo, o atalho instalado mantinha o ícone antigo. Solução: renomear os arquivos (`icon-192-v2.png`, `icon-512-v2.png`, `apple-touch-icon-v2.png`, `favicon-v2.ico`) + manifest versionado (`manifest-v2.webmanifest`). Nome de arquivo novo = URL nova = o browser busca de novo, sem depender de query string.

## 2. Ícone mobile recomposto com nome completo legível

O emblema sozinho ficava ilegível/pouco identificável no launcher. Recomposição: emblema + "ANPEREZ MONEY" ampliados, fundo em degradê da arte original (`manifest v3` → `manifest-v2.webmanifest` apontando para ícones v3).

- **maskable v3 → v4**: a v3 tinha o nome com 90% da largura e o launcher da Samsung (máscara circular) cortava/esticava o texto. A v4 recompõe tudo (emblema + ANPEREZ + MONEY) dentro do círculo central de 80% (área segura do maskable) — nada é cortado, em troca o conjunto fica um pouco menor no quadro.
- **`short_name`**: valia "ANPEREZ" e era esse o texto sob o ícone; trocado para **"ANPEREZ Money"**.

## 3. Verificação automática de versão (fura deploy antigo em cache)

`vite.config.js` gera `__VERSAO_APP__` + `dist/versao.json`; hook `useVerificarVersao` compara a versão local com `versao.json` (no-store) no mount + `visibilitychange`; faixa azul "Nova versão disponível — Atualizar agora" força reload. Versão do build passou a incluir segundos (evitava colisão em pushes no mesmo minuto).
