# 01/09/2026 — Recorrência vira SÉRIE mensal + edição completa no Planejamento

Resolvidos os dois problemas apontados no Planejamento: (1) o modo **[Recorrente]**
gerava uma previsão avulsa de UM mês, em vez de uma série mensal que se repete;
(2) a edição de um lançamento era só um modal de destino Conta/Cartão, não um
formulário completo.

---

## Problema 1 — Recorrência vira SÉRIE mensal

### Antes
`GeradorRecorrenciaMensal` criava uma única previsão avulsa (`origem='recorrente'`
sem `serie_id`). Para ter "Netflix" todos os meses era preciso reabrir o form a
cada mês.

### Decisões (com André)
- **Dia de vencimento (1–31), não data fechada.** O usuário informa "dia 10" e a
  série ancora nesse dia, com **clamp de fim de mês (D2)**: dia 31 em fevereiro
  vira 28 (29 em bissexto), preservando a âncora 31 nos meses seguintes.
- **Término opcional.** Com término = a série para no mês da data informada
  (inclusive). Sem término = recorrência **indefinida**, materializada num
  **horizonte inicial fixo de 24 meses** (constante nomeada
  `HORIZONTE_RECORRENCIA_SEM_TERMINO_MESES`), **prorrogável depois** via a infra
  de regeneração já existente (`regenerarSerie`/`calcularRegeneração`).
- **Coluna `serie_data_termino date`** (migration 21), nullável, aditiva e
  idempotente. É **metadado informativo** por linha: a UI deriva os meses/
  `total_parcelas`, e uma regeneração futura pode reapresentar o término. `NULL`
  = recorrente indefinida (ou parcelada/avulsa).

### Implementação
- `src/lib/recorrenciaCalc.js` (nova, funções PURAS testadas):
  - `HORIZONTE_RECORRENCIA_SEM_TERMINO_MESES = 24`;
  - `mesesAteTermino(mesInicial, dataTermino)` → ≥1, rejeita término anterior;
  - `totalParcelasRecorrencia(mesInicial, dataTermino)` → sem término = 24;
  - `primeiroVencimento(mesInicio, dia)` → clamp fim de mês.
- `src/lib/parcelas.js`: nova `repetirValorEmOcorrencias(dados)` — repete o
  **MESMO valor** (`valorCentavos`) em `totalParcelas` ocorrências mensais via
  `dataDaParcela('mensal')`, propagando `serieDataTermino` opcional + origem/
  conta/observação. Não toca em `dividirValorEmParcelas`.
- `src/lib/planejamentoSerie.js`: `montarLinhasRecorrentes(dados)` — usa
  `repetirValorEmOcorrencias` e calcula `ano_semana`/`semana` via `semanaIso`
  por linha; estado 'previsto'; carrega `serie_data_termino` quando presente.
- `src/hooks/usePlanejamentos.js`: `criarSerieRecorrente(dados)` (uuid →
  `montarLinhasRecorrentes` → insert batch → `atualizar()`), exposta no hook.
- `src/pages/Planejamento.jsx`: `acoes.criarSerieRecorrente`.
- `src/components/planejamento/GeradorRecorrenciaMensal.jsx`: campos **Mês de
  início** (`type="month"`), **Dia do vencimento** (1–31) e **Data de término
  (opcional)**; botão "Gerar série de MÊS/ANO (N meses)"; painel de resumo
  "até DATA (N meses)" ou "indefinida (24 meses — prorrogável)"; envia pelo novo
  contrato `aoCriarSerie` (`totalParcelas`, `valorCentavos`,
  `dataPrimeiraParcela`, `origem:'recorrente'`, `serieDataTermino`…). Fallback
  `aoCriar` (avulso de 1 mês) mantido só para o `GeradorDasMei` preservado como
  referência.
- `GeradorCondominio.jsx`: recebe e repassa `aoCriarSerie`.

### Limitação assumida (documentada no componente)
O valor do **mês de referência** (1º mês, `calcularValor(mesInicial)`) é
**repetido** nas N ocorrências. Para DAS-MEI/assinaturas de valor fixo é exato;
para **Condomínio** (média móvel variável) o valor fica congelado no do mês
inicial — melhoria futura via regeneração.

### Migration 21 (`supabase/21_serie_data_termino.sql`)
Aditiva/idempotente: `alter table public.planejamentos add column if not exists
serie_data_termino date;` + comment explicando o metadado. **RODAR NO SQL
EDITOR** junto com a revisão.

## Problema 2 — Edição completa em formulário pré-preenchido

### Antes
O botão "Editar" abria um modal só de destino Conta/Cartão, e alterar
descrição/valor/data exigia excluir e recriar.

### Decisões (com André)
- **Formulário completo** no padrão `EditarCompraForm` (descrição, valor com
  vírgula, data prevista, tipo Entrada/Saída, destino Conta/Cartão) pré-preenchido
  com o item.
- **Salvar só o que mudou**: `montarAlteracoesEdicao` (função pura) devolve `{}`
  se nada mudou; nunca sobrescreve campos não tocados. O `editarPlanejamento` do
  hook já é parcial e recalcula `ano_semana`/`semana` se `data_prevista` mudar.
- **Série: edição vale só para a OCCORRÊNCIA atual** (não propaga para a série).
  Propagação via `regenerarSerie` fica para o futuro.
- **Destino**: "Conta" no destino **limpa o direcionamento** (`destino_padrao:
  null`, `cartao_padrao_id: null` — não mexe em `conta_destino_id`); "Cartão"
  grava `destino_padrao='cartao'` + `cartao_padrao_id` (troca de cartão mantém o
  destino). Só altera direcionamento quando o usuário muda o toggle/select.
- **Itens de fatura** (`item.fatura === true`): `realizada` é **projeção
  dinâmica** — SEM formulário de edição (mantido sem ações, como antes). Itens
  realizados podem ser editados normalmente.

### Implementação
- `src/lib/edicaoPlanejamento.js` (nova, pura): montar alterações parciais.
- `src/components/EditarPlanejamentoForm.jsx` (novo): form completo pré-preenchido
  com nota "pertence a uma série — edição vale só para esta ocorrência" quando
  `serie_id` presente.
- `src/components/planejamento/Lancamentos.jsx`: modal antigo substituído pelo
  `<EditarPlanejamentoForm>`; `aoSalvarEdicao(id, alteracoes)` = `acoes.editar` →
  fecha → `aoPosMutacao?.()`; botões "Editar" → "Editar planejamento";
  instâncias [Recorrente]/[Condomínio] com `aoCriarSerie={acoes.criarSerieRecorrente}`.

## 01/09/2026 (7ª leva) — Férias por INTERVALO (migration 25) + saldo de 15 dias/ano + valores na Configurações

Evolução do módulo Ponto decidida com o André: as férias **deixam de ser
exceções avulsas** (`ponto_excecoes` tipo `ferias`, dia a dia) e passam a ser
**intervalos** com controle de saldo, e a **edição de valores** (fixo/HE/domfer)
sai do módulo para a página **Configurações**.

### Decisões (com André)
- **Férias = intervalo**: tabela `ponto_ferias` com `data_inicio`/`data_fim`
  (dia único = início == fim), `obs`, e **saldo de 15 dias/ano** (constante
  `QUOTA_FERIAS_ANUAL = 15`). Saldo por **ano de calendário**: intervalo
  cruzando ano conta dias em cada um (mensagem "restam X de 15 dias em ANO").
- **Sem sobreposição**: exclusion constraint `daterange(data_inicio, data_fim, '[]') &&`
  (btree_gist) impede períodos que se tocam — evita reservar o mesmo dia duas vezes.
- **Migração do legado**: exceções `ferias` antigas (avulsas) são convertidas em
  intervalos de 1 dia e **removidas** de `ponto_excecoes` — o resumo passa a
